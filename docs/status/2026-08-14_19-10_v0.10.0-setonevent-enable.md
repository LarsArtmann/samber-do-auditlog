# Status: v0.10.0 — SetOnEvent + Enable (Late-Wiring APIs)

**Date**: 2026-08-14
**Session scope**: `Plugin.SetOnEvent` + `Plugin.Enable`, released as v0.10.0, driven by BuildFlow's empty DI SSE stream
**Commits**: `7cfaa49`, `f2c1b97`, `5ac26b9` (daemon), `b80152a` (release prep) — tag `v0.10.0` pushed

## a) FULLY DONE

### Root cause from the consumer side (BuildFlow's unified live dashboard)

The DI tab's `/api/events` SSE stream was empty for TWO independent reasons:

1. **Callback captured at `New()` time.** BuildFlow creates the plugin before its CLI flags are parsed (cmdguard consumes it via `WithAuditLog`), so `Config.OnEvent` could never reference the SSE hub, which only exists after flag parsing. The consumer-side refactor alternative was architecturally blocked.
2. **Plugin created disabled (undocumented).** Without `DO_AUDITLOG_ENABLED`, `Opts()` returns empty hooks — zero events recorded even with a wired callback. A naive E2E test would have masked this defect.

### `Plugin.SetOnEvent(fn func(Event))` (plugin.go, recorder.go, hooks.go)

- Sets or replaces the event callback after `New()`.
- Race-safe: dedicated `onEventMu sync.RWMutex` on `Recorder`, deliberately separate from `mu` (callback fires outside `mu` by design). `fireEvent` copies the callback under `RLock` and invokes the copy outside any lock; `setOnEvent` takes `Lock` only on swap.
- Replaces (does not chain) `Config.OnEvent`; doc points to `MultiWriter` for multi-sink composition.
- No replay of pre-wiring events (the live dashboard's connect-time snapshot covers it).
- 4 tests: subsequent-events-only, nil-disables, replaces-configured, concurrent-swap-while-recording (race detector).

### `Plugin.Enable()` (plugin.go)

- Turns logging on after `New()` regardless of `Config.Enabled`/env. Idempotent.
- Documented constraint: effective only before the first `Opts()` result is consumed by an injector (plain field write, unsynchronized by design).
- 1 test: installs hooks when called before `Opts()` (uses `t.Setenv`, not parallel).
